# Architecture

## System Overview

Helix Orchestration is a distributed lab automation platform that coordinates fumehoods, scientific instruments, analytical devices, workflow execution, and trend data streams across two operational tiers. The **Agent** tier runs one process per fumehood — it owns local execution, device control, and safety enforcement. The **Site Server** tier aggregates, compiles WSL workflows, manages campaigns, and provides the external API. The core domain library is headless, transport-agnostic, and UI-agnostic.

## Architectural Style

- **Two-tier distributed system**: Site Server (site-wide) + Agent (per fumehood)
- **Modular Monolith per process**: each host is a single deployable; boundaries enforced by projects
- **Clean Architecture within each process**: Core domain has no outward dependencies; infrastructure projects depend inward
- **Interface-first**: every subsystem boundary is an interface; backends are swappable (sim vs real)

## Key Domain Concepts

- **RunspaceDefinition**: compiled execution contract produced by the WSL compiler; JSON; consumed by Agent
- **Runspace / DurableRunspace**: one workflow instance container with its own `ExperimentContext`, device leases, and durable Cleipnir continuation state
- **WorkflowContext**: the single DI surface injected into a workflow -- carries Capabilities, Trends, Safety, State, Experiment
- **ICapabilityInvoker / CapabilityRegistry**: dispatches named capability verbs (e.g. `SetTemperature`) to the correct device adapter; workflows never see protocols
- **WSL (Workflow Specification Language)**: JSON declarative authoring format; generated by UI/chatbot/ELN/ML; compiled at Site Server to `RunspaceDefinition`
- **Campaign**: Site Server-owned multi-experiment orchestration unit (DoE grids, ML loops, sweeps); agents only execute single experiments
- **ITrendProvider**: typed accessors for all trend kinds; supports derived trend registration
- **IDeviceLeasingService**: exclusive/shared lease acquisition, heartbeat renewal, timeout reclamation
- **ISafetyEngine**: evaluates `InterlockRule` predicates, triggers `EmergencyStopToken` on critical violations
- **ExperimentContext**: lifecycle state machine (Created -> Running -> Suspended -> Completed/Failed); every measurement tagged with `ExperimentId`
- **IAgentProxy**: seam between Site Server and Agent -- `SimAgentProxy` for dev/test, `GrpcAgentProxy` for production

## Data Flow

### Experiment Submission Path

```
WSL JSON (UI / Chatbot / ELN / ML)
    |
Site Server Workflow Compiler
    | validate schema -> resolve devices -> inject safety envelope
RunspaceDefinition JSON
    | gRPC
Agent RunspaceManager
    | acquire leases -> create ExperimentContext -> execute capabilities
DurableRunspace (Cleipnir-backed)
    | persist continuation state
Runspace completes / suspends / fails -> results -> Site Server
```

### Trend Data Flow

```
Physical Device / Vendor SDK
    |
Device Adapter -> ITrendProvider
    |
IScalarTrend<T>  --> TrendWindow<T> -> TrendFunctions (IsStable, Slope, etc.)
ISpectralTrend   --> SpectralScan window + IObservable<SpectralScan>
IDiodeArrayTrend --> 2D matrix + slice stream
IImageTrend      --> IObservable<ImageFrame> -> MinIO/S3
IVideoTrend      --> IObservable<VideoSegment> -> MinIO/S3
IDerivedTrend    --> MathExpression / PythonScript / CSharpDelegate
    |
MQTT publish (MqttTrendPublisher)
    |
Site Server MQTT bridge -> WebSocket event hub -> UI
    |
Recorder Worker -> JSONL batch -> MinIO/S3
```

## Key Design Patterns

| Pattern | Where Used | Why |
|---------|------------|-----|
| Registry / Dispatch | `CapabilityRegistry`, `WorkflowRegistry`, `AdapterRegistry` | Decouple callers from implementations |
| Strategy | `IAgentProxy` (sim vs gRPC), transport implementations | Swap backends without changing business logic |
| Hosted Service | `LeaseExpiryWorker`, `MqttRecorderService`, `RecorderWriterService` | Long-running background loops with DI and cancellation |
| Proxy / Adapter | `GrpcAgentProxy`, `AdapterProxy`, `WslExecutionAdapter` | Isolate protocol details from domain |
| Builder / Descriptor | `DeviceDescriptor`, `RunspaceDefinition`, `DerivedTrendDefinition` | Immutable configuration objects across layer boundaries |
| Bounded Channel | `RecorderWriterService` | Back-pressure-aware queue between MQTT ingestion and storage writer |
| Interface-first | All subsystem boundaries | Every backend is swappable; enables hardware-free testing |
| Minimal API Groups | SiteServer REST endpoints | Grouped endpoint registration without controller overhead |

## Architectural Constraints

- **Threading**: safety engine and workflow execution must be cancellable via `EmergencyStopToken` (CancellationToken)
- **Persistence boundary**: Core has no persistence dependencies; all storage via `IWorkflowStateStore`, `IDeviceLeasingService` interfaces
- **Simulation switch**: `IAgentProxy` and `ITrendProvider` toggle between sim and real at DI registration time
- **Campaign isolation**: Site Server owns campaign state; Agent executes one experiment at a time
- **No network for safety**: safety engine evaluates locally against in-process trend data only

## Cross-Cutting Concerns

- **Telemetry**: `HelixTelemetry` uses `System.Diagnostics.Activity` (OpenTelemetry-compatible)
- **Logging**: `ILogger<T>` throughout; no direct Console usage in library code
- **Configuration**: `IOptions<T>` pattern; config files are `appsettings.json`, `agent-config.json`, and `device-registry.json`
- **Error handling**: exceptions bubble to runspace boundary; durable execution handles retry via Cleipnir
