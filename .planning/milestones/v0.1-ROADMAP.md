## Overview

A distributed lab automation platform that enables scientists to build visual workflows, connect real lab hardware, execute automated experiments, and visualise live data without writing code. Milestone v0.1 delivers: 48 device drivers ported, Tauri desktop app with Rete.js workflow builder + live telemetry, site dashboard (React/Vite), Docusaurus documentation, Docker deployment stack, and all 5 integration blockers from the audit closed.

## Milestone Summary

### Decimal / Inserted Phases

- Phase driver-port: Driver port overflow from Phases 2-3; 48 drivers needed dedicated scale
- Phase 6.1: Device manual control and CapabilityDescriptor schema (post-Phase 6 gap)
- Phase 6.2: DeviceAction palette and live execution state (post-6.1 gap)
- Phase 6.3: Integration blocker fixes from milestone audit (C1/C4/C7/C8/C9)
- Phase 6.4: Remaining audit blockers (D5/D6/E1-E4/G2)

### Key Decisions

- DeviceAdapterBase composition model -- enables transport seam testing without real hardware
- Tauri + Rete.js for local UI -- cross-platform desktop with visual WSL authoring
- Cleipnir PostgreSQL store for durable execution -- runspace state survives Agent restart
- OPC Foundation library replacing Opc.UaFx.Advanced (removed commercial dependency)
- tauri-plugin-fs for workflow library -- built-in persistence, type-safe
- BaseSchemes as NodeEditor type parameter in rete@2.0.6 (ClassicPreset.Schemes does not exist)
- vi.hoisted() + vi.mock("recharts") for all recharts tests (SVG renderer errors in jsdom)
- isAnimationActive=false on recharts Line/Area components (animation causes test failures in jsdom)
- LazyStore (sync constructor) over Store in @tauri-apps/plugin-store v2.4.3
- depends_on uses service names not container_name aliases in Docker Compose
- DeviceRegistry populated via factory lambda from CapabilityRegistry.GetAllCapabilityNames() in Agent

### Issues Resolved

- CapabilityRegistry empty singleton -- fixed Phase 1 + Phase 6.3 bridge
- InMemoryFunctionStore replaced with Cleipnir PostgreSQL (Phase 1)
- Opc.UaFx.Advanced commercial dependency removed (Phase 1)
- helix-desktop 76 tests not in CI -- helix-desktop-test job added (Phase 6.4)
- Agent missing gRPC server -- AgentGrpcService.cs with 5 RPC overrides (Phase 6.4)
- docker-compose SiteServer missing ConnectionStrings__HelixOrchestration (Phase 6.4)
- POST /devices/{id}/execute always 404 -- adapter prefix guard fixed (Phase 6.3)
- DeviceRegistry.tsx fetching /health instead of /devices (Phase 6.3)

### Issues Deferred to v0.2

- CORS policy not configured in SiteServer -- dev works via Vite proxy; production needs AddCors/UseCors
- DeviceStatusEvent emits full capability key as deviceId (e.g. "simulator.SetFlow") instead of adapter prefix
- WorkflowBuilder.tsx useState misuse for async load -- functional but stale closure risk
- SciChart integration -- placeholder wrapper only; recharts used for production charts
- Human verification items outstanding: Tauri runtime UI tests (5), Docusaurus rendered site (2), docker-compose live run (4), setup.ps1 clean machine (1), systemd on Debian 12 (1)
- Phases 1-3 have no formal VERIFICATION.md (SUMMARY task tables only)

### Technical Debt Incurred

- Phases 1-4: no VERIFICATION.md -- completion confirmed via SUMMARY task tables only
- Phase 5: 5 human-verification items require live Tauri runtime + Agent
- Phase 7: SiteServer missing AddCors/UseCors -- production CORS policy needed
- Phase 9: 2 human-verification items (rendered site visual check, adapter authoring usability)
