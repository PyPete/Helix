# Phase 6.2 Plan 02: Live Execution State + Step Timing Summary

**One-liner:** useNodeExecutionState hook maps Agent WebSocket events to per-node execution states; NodeTimingFooter sub-component surfaces elapsed/ETA/duration on all 8 node types; WorkflowBuilder wired to update node/edge state live from runspaceEvents.

## What Was Built

### Task 1: C# changes + TypeScript types + useNodeExecutionState hook

**CapabilityDescriptor.cs:**
- Added `int? EstimatedDurationMs = null` as the last optional positional parameter
- No call sites changed — backward compatible

**RunspaceEvent.cs StepStartedEvent:**
- Added `int? EstimatedDurationMs = null` as 4th optional positional parameter
- All existing 3-arg call sites continue to compile

**agent.ts RunspaceEvent interface:**
- Added `estimatedDurationMs?: number` alongside the existing index signature

**useNodeExecutionState.ts (new):**
- `useMemo` reduce-over-events pattern: processes `RunspaceEvent[]` into `Record<string, NodeExecutionState>`
- Event handling:
  - `step-started`: sets `{ executionState: "running", startedAt, estimatedCompletionAt? }`
  - `step-completed`: sets `{ executionState: "succeeded", finishedAt }`
  - `step-faulted`: sets `{ executionState: "failed", faultMessage }`
  - `runspace-started`: clears all accumulated states (for-loop delete pattern)
  - all other types: no change
- `edgeExecutionStates`: a `useMemo` returning a function that maps edges to their source node's state
- Security guards: `stepId = String(event["stepId"] ?? "")` with skip-if-empty (T-6.2-04); `isNaN` guard on `Date.parse` for estimatedCompletionAt (T-6.2-05)

**useNodeExecutionState.test.ts (new):**
- 8 tests covering all event type transitions and edge state mapping
- All 8 pass

### Task 2: NodeTimingFooter + useHelixFlow + WorkflowBuilder wiring

**HelixNodes.tsx:**
- Extended `HelixNodeData` interface with `startedAt?`, `estimatedCompletionAt?`, `finishedAt?`, `faultMessage?` (all ISO string)
- Extended `DeviceActionNodeData` with the same 4 timing fields
- Added internal `NodeTimingFooter` component:
  - `idle` / undefined state: returns null
  - `running`: amber `data-testid="timing-footer-running"` with `formatHHMMSS(elapsed)` + optional ETA
  - `succeeded`: green `data-testid="timing-footer-succeeded"` with "Finished in Xm Ys"
  - `failed`: red `data-testid="timing-footer-failed"` with "Failed at HH:MM:SS"
  - `isNaN` guard applied on all `Date.parse` results
- Added `NodeTimingFooter` to all 8 node types: Step, Condition, Branch, Loop, Parallel, Delay, WaitFor, DeviceAction

**useHelixFlow.ts:**
- Added `setNodes: Dispatch<SetStateAction<HelixNode[]>>` and `setEdges: Dispatch<SetStateAction<HelixEdge[]>>` to `UseHelixFlowResult` interface and return value

**WorkflowBuilder.tsx:**
- Added `useEffect` import
- Imported `useAgentWebSocket` and `useNodeExecutionState`
- Destructured `setNodes` and `setEdges` from `useHelixFlow()`
- Called `useAgentWebSocket(baseUrl)` to get `runspaceEvents`
- Called `useNodeExecutionState(runspaceEvents)` to get `nodeStates` and `edgeExecutionStates`
- Added `useEffect([nodeStates, setNodes])`: maps nodes → merges execution state + timing ISO strings into `node.data`
- Added `useEffect([nodeStates, edgeExecutionStates, setEdges])`: maps edges → sets `data.executionState` from `edgeExecutionStates(eds)`

**HelixNodes.test.tsx (new):**
- 5 tests covering NodeTimingFooter rendering for all 4 states (idle, running, succeeded, failed + undefined)
- Tests exercise `data-testid="timing-footer-running/succeeded/failed"`

**WorkflowBuilder.test.tsx:**

- Uses `MockWebSocket` class pattern (stub `global.WebSocket`) to inject a step-started event and assert `timing-footer-running` appears
- All 15 WorkflowBuilder tests pass

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] V8 address space crash when adding vi.mock() to WorkflowBuilder.test.tsx**
- **Found during:** Task 2 — adding `vi.mock("../../hooks/useNodeExecutionState")` to `WorkflowBuilder.test.tsx`
- **Issue:** Adding ANY new `vi.mock()` call to the test file caused the Vitest worker process to crash with `FATAL ERROR: Ineffective mark-compacts near heap limit` and V8 `AddressSpaceReservation` errors. The existing file already mocks 3 large modules (reactflow, DevicePalette, workflowLibrary); adding a 4th exhausts the child process's virtual address space on this machine.
- **Fix:** Two-pronged approach:
  1. Created `HelixNodes.test.tsx` as a new lightweight test file for `NodeTimingFooter` rendering (5 tests). This file only mocks `reactflow` and successfully tests all 4 execution states.
  2. Used `MockWebSocket` class pattern in `WorkflowBuilder.test.tsx` for the integration test — stubs `global.WebSocket` without adding any `vi.mock()` calls. The test injects a real `step-started` message through the actual `useAgentWebSocket` + `useNodeExecutionState` pipeline, providing stronger integration coverage than the plan's mocked alternative.
- **Files modified:** `WorkflowBuilder.test.tsx`, created `HelixNodes.test.tsx`

**2. [Rule 2 - Missing functionality] import type React added then simplified**
- Added `import type React from "react"` to `HelixNodes.tsx` to type `React.CSSProperties` in `NodeTimingFooter` — necessary since the JSX transform doesn't provide the React namespace for type references.
