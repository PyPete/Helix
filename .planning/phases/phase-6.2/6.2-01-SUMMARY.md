# Phase 6.2 Plan 01: DeviceAction Node, Device Palette, Hybrid Ports Summary

**One-liner:** DeviceAction ReactFlow node driven by CapabilityDescriptor schema, left-panel DevicePalette with drag-to-canvas, hybrid static/dataflow ports, exportWsl mapping to WslDocument Step nodeType.

## What Was Built

### Task 1: DeviceActionNodeComponent in HelixNodes.tsx

- Extended `HelixNodeType` union with `"DeviceAction"`
- Exported `DeviceActionNodeData` interface with `adapterId`, `capability`, `parameters: ParameterSchema[]`, `fieldValues`
- Exported `PORT_COLOURS` constant following Blender-convention: `Numeric=#5b8dd9`, `Enum=#e67e22`, `Boolean=#27ae60`, `String=#e91e8c`, `Duration=#5b8dd9`, `exec=#a6adc8`
- `DeviceActionNodeComponent` renders:
  - Header: `{adapterId} › {capability}` with accent colour `#7c3aed`
  - Per-parameter widgets driven by `ParameterSchema.type`: number input (Numeric/Duration), select (Enum), checkbox (Boolean), text input (String)
  - Each parameter has a target Handle on the left with type-matched colour
  - Hybrid logic via `useEdges()`: when an edge targets a parameter handle, hide the form widget and show `data-testid="wire-indicator-{param.name}"` span
  - `exec-in` (target, left) and `exec-out` (source, right) handles always present
- Added `DeviceAction: DeviceActionNodeComponent` to `NODE_TYPES`

### Task 2: DevicePalette + useHelixFlow + WorkflowBuilder extensions

**DevicePalette.tsx:**
- Fetches `{baseUrl}/devices` then `{baseUrl}/devices/{id}/capabilities` in parallel via `Promise.all`
- Renders collapsible `<details data-testid="palette-group-{adapterId}">` per adapter
- Each capability is a draggable card (`data-testid="capability-card-{adapterId}-{verbName}"`)
- `onDragStart` sets `dataTransfer` key `application/helix-capability` with JSON payload `{adapterId, capability, descriptor}`
- Fetch errors display "Failed to load devices" (T-6.2-02 mitigation)

**useHelixFlow.ts:**
- Added `addDeviceActionNode(adapterId, capability, descriptor, position?)` to hook and `UseHelixFlowResult` interface
- Updated `exportWsl()` to branch on `nodeType === "DeviceAction"`: serialises as `nodeType: "Step"` with `parameters.capability = "{adapterId}.{capability}"`

**WorkflowBuilder.tsx:**
- Flex layout wrapping `DevicePalette` (220px left panel) + canvas div (`flex: 1`)
- `handleDrop` on `rete-canvas` wrapper div reads `application/helix-capability`, parses with try/catch (T-6.2-01), calls `addDeviceActionNode` at `rfInstance.screenToFlowPosition`
- `onDragOver` calls `e.preventDefault()` to allow drops
- `CANVAS_STYLE.height` changed from `"600px"` to `"100%"` (inherits from flex container)

**DevicePalette.test.tsx (4 tests):**
- palette-group-Alicat renders after fetch resolves
- capability-card element has `draggable=true`
- dragstart fires `dataTransfer.setData` with `application/helix-capability`
- fetch error shows "Failed to load devices"

**WorkflowBuilder.test.tsx (2 new tests):**
- drop on rete-canvas creates DeviceAction node (data-testid visible)
- exportWsl after DeviceAction drop returns nodeType "Step" with `parameters.capability = "Alicat.SetFlow"`

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing functionality] ReactFlow mock extended to render node components**
- **Found during:** Task 2 test writing
- **Issue:** The existing ReactFlow mock rendered only `{children}` passed to it — it did not call `nodeTypes[type]` for each node in the `nodes` prop. This meant `DeviceActionNodeComponent` (with its `data-testid`) was never rendered in jsdom tests.
- **Fix:** Extended the `vi.mock("reactflow", ...)` mock in `WorkflowBuilder.test.tsx` so that `ReactFlow` now maps over `nodes` and renders each `nodeTypes[node.type]` component. Also added `Handle` and `Position` exports to the reactflow mock since `DeviceActionNodeComponent` imports them.
- **Files modified:** `WorkflowBuilder.test.tsx`

**2. [Rule 2 - Missing functionality] useEdges mock added to reactflow**
- **Found during:** Task 2 — `DeviceActionNodeComponent` calls `useEdges()` from reactflow
- **Fix:** Added `useEdges: vi.fn(() => [])` to the reactflow module mock so the hook resolves without error in jsdom.
- **Files modified:** `WorkflowBuilder.test.tsx`

**3. [Rule 2 - Security] handleDrop try/catch per T-6.2-01**
- Applied per threat model: JSON.parse wrapped in try/catch, drops with missing `adapterId`/`capability`/`descriptor` fields are silently ignored.
