<task type="auto">
  <name>Task 1: setup.ps1 — Windows idempotent bootstrap script</name>
  <files>
    setup.ps1

  <action>
Create setup.ps1 at the repository root. The script must use PowerShell 5.1+ syntax (no PowerShell 7-only features; $PSVersionTable.PSVersion.Major -ge 5 guard is fine). Run with: .\setup.ps1

Script structure — each step prints "[STEP N] Checking/Installing X..." then either "  PASS: ..." or "  FAIL: ..." and sets $failed=$true on failure. At the end, if $failed, print "Setup FAILED. Fix the issues above and re-run." and exit 1. Otherwise print "Setup complete. Helix stack is running." and exit 0.

Step 1 — Check .NET 10 SDK:
  Run: dotnet --version 2>$null
  If exit code != 0 or version does not start with "10.", print install instructions for winget:
    winget install Microsoft.DotNet.SDK.10
  If winget is not available, print URL: https://dotnet.microsoft.com/download/dotnet/10.0
  After install attempt, re-check. If still missing, FAIL.
  Idempotent: if already installed and >= 10.0, print PASS and continue.

Step 2 — Check Node.js 20+:
  Run: node --version 2>$null
  If not present or version < 20, attempt: winget install OpenJS.NodeJS.LTS
  Re-check. If still missing, FAIL.
  Parse major version from output: $major = [int]($version -replace 'v(\d+).*','$1')

Step 3 — Check Docker Desktop:
  Run: docker info 2>$null
  If exit code != 0, print "Docker Desktop is required. Install from https://www.docker.com/products/docker-desktop" and FAIL.
  Do NOT attempt to install Docker automatically — it requires a GUI installer and machine restart.

Step 4 — dotnet build solution:
  Run: dotnet build Helix.Orchestration.slnx -c Release --nologo
  If exit code != 0, FAIL.

Step 5 — npm ci + npm run build for helix-dashboard:
  Run: cd helix-dashboard; npm ci; npm run build; cd ..
  Use Push-Location / Pop-Location. If either command fails, FAIL.

Step 6 — docker compose up -d:
  Run: docker compose up -d --build
  If exit code != 0, FAIL.

Step 7 — Wait for stack health (optional but helpful):
  Run: docker compose ps (parse output for "healthy" or just print the table for the user to read)
  Print: "Run 'docker compose ps' to check service health."

Important idempotency rules:
- dotnet build is always re-run (fast, safe)
- npm ci is safe to re-run (deletes and reinstalls node_modules)
- docker compose up -d is idempotent (starts stopped containers, skips running ones)
- winget install is idempotent on Windows 11 (no-ops if already installed)

The script must not require Administrator rights for steps 1-2 (winget works per-user). Step 6 (docker) requires Docker Desktop to be running. Print a warning if docker info fails: "Ensure Docker Desktop is running."

<task type="auto">
  <name>Task 2: setup.sh — Linux/Raspberry Pi bootstrap script with systemd unit installation</name>
  <files>
    setup.sh
  </files>
  <action>
Create setup.sh at the repository root with #!/usr/bin/env bash, set -euo pipefail. The script must be POSIX bash-compatible (runs on Debian 12, Ubuntu 22.04, Raspberry Pi OS Bookworm). Make executable: chmod +x setup.sh.

Use the same PASS/FAIL step pattern as setup.ps1. Define helper functions:
  pass() { echo "  PASS: $1"; }
  fail() { echo "  FAIL: $1"; FAILED=1; }
Initialize FAILED=0 at top. At end: if [ "$FAILED" -eq 1 ]; then echo "Setup FAILED. Fix the above and re-run."; exit 1; fi

Step 1 — Check .NET 10 SDK:
  dotnet --version 2>/dev/null; if missing or < 10.x, install via Microsoft's apt repo:
    wget https://packages.microsoft.com/config/debian/12/packages-microsoft-prod.deb -O /tmp/packages-microsoft-prod.deb
    sudo dpkg -i /tmp/packages-microsoft-prod.deb
    sudo apt-get update -y
    sudo apt-get install -y dotnet-sdk-10.0
  Re-check after install. If still missing, fail.

Step 2 — Check Node.js 20+:
  node --version 2>/dev/null; if missing or < 20, install via NodeSource:
    curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
    sudo apt-get install -y nodejs
  Re-check. If still missing, fail.

Step 3 — Check Docker + docker compose:
  docker info 2>/dev/null; if missing:
    sudo apt-get install -y docker.io docker-compose-plugin
  Also ensure current user is in docker group: sudo usermod -aG docker $USER (print note that re-login may be required)
  docker compose version check: docker compose version 2>/dev/null

Step 4 — dotnet build:
  dotnet build Helix.Orchestration.slnx -c Release --nologo
  If exit code != 0, fail.

Step 5 — npm ci + npm run build for helix-dashboard:
  (cd helix-dashboard && npm ci && npm run build)

Step 6 — Install systemd unit files (only if systemd is available: command -v systemctl):
  If systemctl is available:
    sudo cp deploy/systemd/helix-agent.service /etc/systemd/system/helix-agent.service
    sudo cp deploy/systemd/helix-recorder.service /etc/systemd/system/helix-recorder.service
    sudo systemctl daemon-reload
    sudo systemctl enable helix-agent helix-recorder
    sudo systemctl start helix-agent helix-recorder
    pass "helix-agent and helix-recorder systemd services installed and started"
  Else:
    pass "systemd not available; skipping service installation (Docker-only mode)"

Step 7 — docker compose up -d:
  docker compose up -d --build
  If exit code != 0, fail.

SCRIPT_DIR detection: Use SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)" so paths are correct regardless of where the user runs the script from. Use $SCRIPT_DIR/ prefix for all relative paths within the script.

The systemd unit files referenced in Step 6 (deploy/systemd/helix-agent.service and deploy/systemd/helix-recorder.service) will be created by Plan 10-03. Include a guard in setup.sh:
  if [ ! -f "$SCRIPT_DIR/deploy/systemd/helix-agent.service" ]; then
    fail "deploy/systemd/helix-agent.service not found — run after Plan 10-03 completes"
    FAILED=1
  fi
This makes the dependency explicit without crashing the script.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Script → network | setup.sh fetches packages from Microsoft and NodeSource apt repos over HTTPS |
| Script → system | setup.sh uses sudo for apt-get and systemctl — requires operator trust |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-04 | Tampering | apt package fetch over HTTP redirect | mitigate | Use HTTPS URLs for all wget/curl fetches; packages signed by Microsoft/NodeSource GPG keys |
| T-10-05 | Elevation of Privilege | setup.sh uses sudo | accept | Setup scripts are run by an operator who has sudo; documented requirement |
| T-10-06 | Tampering | npm/pip/cargo installs | mitigate | npm ci uses lockfile (package-lock.json) — no floating resolution; no pip/cargo installs in this plan |
| T-10-SC | Tampering | npm ci supply chain | mitigate | npm ci is lockfile-bound; helix-dashboard/package-lock.json is committed to repo |
</threat_model>
