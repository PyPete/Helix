  Agent uses mcr.microsoft.com/dotnet/aspnet:10.0 (gRPC + Kestrel HTTP endpoint)
  SiteServer uses mcr.microsoft.com/dotnet/aspnet:10.0 (ASP.NET Core)
  Recorder uses mcr.microsoft.com/dotnet/runtime:10.0 (Worker SDK, no HTTP listener)
  WORKDIR /app
  COPY --from=build /app/publish .
  EXPOSE the listening port (Agent: 5080; SiteServer: 5090; Recorder: none)
  ENTRYPOINT ["dotnet", "<ProjectName>.dll"]

Important build context: All three Dockerfiles will be built from the repository root (docker compose build sets context to the repo root). The COPY paths in the Dockerfiles must be relative to the repo root â€” e.g., COPY Helix.Orchestration.Agent/ Helix.Orchestration.Agent/ not just COPY . .

The SiteServer has no explicit Kestrel port in appsettings.json (it runs on the default ASP.NET Core ports). Set it explicitly to 5090 via the ASPNETCORE_URLS environment variable in the Dockerfile ENV instruction: ENV ASPNETCORE_URLS=http://+:5090

The Recorder has no HTTP listener; do not add EXPOSE.

Do not add a .dockerignore at this step; the compose file will set build contexts explicitly.

  build:
    context: .

  container_name: helix-agent
  restart: unless-stopped
  ports:
    - "5080:5080"
  environment:
    Kestrel__Endpoints__Http__Url: http://0.0.0.0:5080
    Mqtt__BrokerHost: helix-mosquitto

    ConnectionStrings__HelixOrchestration: Host=helix-postgres;Port=5432;Database=helix_orchestration;Username=helix;Password=helix_dev_password
  depends_on:
    helix-postgres:
      condition: service_healthy
    helix-mosquitto:
      condition: service_healthy
    helix-minio:
      condition: service_healthy
  healthcheck:
    test: ["CMD", "curl", "-f", "http://localhost:5080/health"]
    interval: 15s
    timeout: 5s
    retries: 5
    start_period: 30s

New service: helix-siteserver
  build:
    context: .
    dockerfile: Helix.Orchestration.SiteServer/Dockerfile
  container_name: helix-siteserver
  restart: unless-stopped
  ports:
    - "5090:5090"
  environment:
    ASPNETCORE_URLS: http://+:5090
    AgentProxy__Mode: grpc
    AgentProxy__GrpcAddress: http://helix-agent:5080
    MqttBridge__BrokerHost: helix-mosquitto
    MqttBridge__BrokerPort: 1883
    MqttBridge__SiteId: site1
    MqttBridge__FumehoodId: fh1
  depends_on:
    helix-agent:
      condition: service_healthy
    helix-mosquitto:
      condition: service_healthy
  healthcheck:
    # SiteServer has no /health endpoint; use TCP probe instead
    test: ["CMD-SHELL", "nc -z localhost 5090 || exit 1"]
    interval: 15s
    timeout: 5s
    retries: 5
    start_period: 30s

New service: helix-recorder
  build:
    context: .
    dockerfile: Helix.Orchestration.Recorder/Dockerfile
  container_name: helix-recorder
  restart: unless-stopped
  environment:
    Minio__ServiceUrl: http://helix-minio:9000
    Minio__AccessKey: minioadmin
    Minio__SecretKey: minioadmin
    Minio__DefaultBucket: helix-recordings
    Recorder__MqttBrokerHost: helix-mosquitto
    Recorder__MqttBrokerPort: 1883
  depends_on:
    helix-mosquitto:
      condition: service_healthy
    helix-minio:
      condition: service_healthy

Retain all existing volumes (mosquitto_data, mosquitto_log, postgres_data, minio_data). No new volumes needed.

Note on /health endpoints: The Agent has a registered /health endpoint (AddHealthChecks + MapHealthChecks in Program.cs) — use curl -f http://localhost:5080/health. The SiteServer does NOT have a /health endpoint — use the TCP probe test: ["CMD-SHELL", "nc -z localhost 5090 || exit 1"] as shown above. Do not add a healthcheck to helix-recorder (Worker SDK, no HTTP listener).

The helix-recorder has no HTTP port; omit its healthcheck (docker compose tolerates services with no healthcheck â€” they are considered "started" immediately).
