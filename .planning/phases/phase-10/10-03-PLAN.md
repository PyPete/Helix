--- deploy/windows/install-agent-service.ps1 ---

Follow the NSSM pattern from adapters/python/pump_simulator/install-windows-service.ps1.

Parameters:
  [string]$InstallPath = "C:\Helix\Agent"      -- path to published Agent output
  [string]$NssmPath = "nssm"                    -- NSSM executable (must be on PATH or full path)
  [string]$DotnetPath = ""                      -- path to dotnet.exe; auto-detected if empty

Auto-detect $DotnetPath if empty:
  $DotnetPath = (Get-Command dotnet -ErrorAction SilentlyContinue).Source
  if (-not $DotnetPath) { Write-Error "dotnet not found on PATH"; exit 1 }

Service name: HelixAgent
Display name: "Helix Orchestration Agent"
Description: "Helix lab automation orchestration agent. Manages device adapters, workflow execution, and gRPC API."
Binary: $DotnetPath
Arguments: $InstallPath\Helix.Orchestration.Agent.dll
AppDirectory: $InstallPath
Start type: SERVICE_AUTO_START

Idempotency: Check if service exists first using sc.exe query HelixAgent. If it exists, stop it (nssm stop HelixAgent) before reinstalling:
  $serviceExists = (sc.exe query HelixAgent 2>&1) -notmatch "FAILED"
  if ($serviceExists) {
    Write-Host "Stopping existing HelixAgent service..."
    & $NssmPath stop HelixAgent
    & $NssmPath remove HelixAgent confirm
  }

After install, set environment variables via nssm set HelixAgent AppEnvironmentExtra:
  Kestrel__Endpoints__Http__Url=http://localhost:5080
  Mqtt__BrokerHost=localhost
  Mqtt__BrokerPort=1883

Then start: & $NssmPath start HelixAgent

Print "HelixAgent service installed and started. It will start automatically on reboot."

Note at top of file: "Requires NSSM (Non-Sucking Service Manager). Download from https://nssm.cc or install via: winget install nssm"

--- deploy/systemd/helix-agent.service ---

Based on the pump-adapter.service pattern from adapters/python/pump_simulator/pump-adapter.service.

[Unit]
Description=Helix Orchestration Agent
Documentation=https://helix.docs (or local docs-site URL)
After=network-online.target postgresql.service
Wants=network-online.target

[Service]
Type=simple
User=helix
Group=helix
WorkingDirectory=/opt/helix/agent
ExecStart=/usr/bin/dotnet /opt/helix/agent/Helix.Orchestration.Agent.dll
Restart=on-failure
RestartSec=10
KillSignal=SIGTERM
TimeoutStopSec=30
StandardOutput=journal
StandardError=journal
SyslogIdentifier=helix-agent

Environment=DOTNET_ENVIRONMENT=Production
Environment=Kestrel__Endpoints__Http__Url=http://localhost:5080
Environment=Mqtt__BrokerHost=localhost
Environment=Mqtt__BrokerPort=1883
Environment=ConnectionStrings__HelixOrchestration=Host=localhost;Port=5432;Database=helix_orchestration;Username=helix;Password=CHANGE_ME

[Install]
WantedBy=multi-user.target

# Type=simple is used because the Agent does not call UseSystemd(); Type=notify would cause systemctl start to timeout waiting for a notification that never arrives.

--- deploy/preflight/preflight.ps1 ---

PowerShell pre-flight check script. Parameters:
  [string]$PostgresHost = "localhost"
  [int]$PostgresPort = 5432
  [string]$PostgresDb = "helix_orchestration"
  [string]$MqttHost = "localhost"
  [int]$MqttPort = 1883
  [string]$MinioEndpoint = "http://localhost:9000"
  [string]$AgentGrpcHost = "localhost"
  [int]$AgentGrpcPort = 5080

Result tracking: $results = @() with each entry being [PSCustomObject]@{Check="..."; Status="PASS"|"WARN"|"FAIL"; Detail="..."}

Check 1 â€” PostgreSQL TCP connectivity:
  Use System.Net.Sockets.TcpClient to attempt TCP connect to $PostgresHost:$PostgresPort with 3s timeout.
  PASS if connects. FAIL if refused or timeout.
  Detail: "TCP connect to $PostgresHost:$PostgresPort"

Check 2 â€” MQTT broker TCP connectivity:
  Same TcpClient pattern to $MqttHost:$MqttPort.
  PASS/FAIL.

Check 3 â€” MinIO HTTP health endpoint:
  Invoke-WebRequest -Uri "$MinioEndpoint/minio/health/live" -TimeoutSec 5 -UseBasicParsing
  PASS if HTTP 200. WARN if connection refused (MinIO may not be running). FAIL if unexpected error.

Check 4 â€” Agent gRPC / HTTP health:
  Invoke-WebRequest -Uri "http://${AgentGrpcHost}:${AgentGrpcPort}/health" -TimeoutSec 5 -UseBasicParsing
  PASS if HTTP 200. WARN if connection refused (Agent may not be running in pre-start scenario). FAIL if unexpected error.
  Note: WARN is appropriate here because pre-flight may run before Agent starts.

Check 5 â€” OPC UA transport config (config-file check, no network required):
  Look for any appsettings.json under Helix.Orchestration.Agent/ (relative to script location ../../ from deploy/preflight/).
  Parse JSON. Check if OpcUa section exists and AutoAcceptUntrustedCertificates is false.
  PASS if set to false. WARN if set to true (insecure). WARN if section not found (OPC UA may not be configured).

Check 6 â€” Serial port existence (Windows only):
  [System.IO.Ports.SerialPort]::GetPortNames() â€” if returns any COM ports, PASS with list. If empty, WARN "No COM ports detected â€” check USB-serial adapters".

After all checks, print a formatted summary table:
  Write-Host ""
  Write-Host "=== Helix Pre-flight Report ==="
  $results | Format-Table -AutoSize

Compute overall exit code:
  $failed = $results | Where-Object { $_.Status -eq "FAIL" }
  $warned = $results | Where-Object { $_.Status -eq "WARN" }
  if ($failed.Count -gt 0) { Write-Host "Result: FAIL ($($failed.Count) failures)"; exit 2 }
  elseif ($warned.Count -gt 0) { Write-Host "Result: WARN ($($warned.Count) warnings)"; exit 1 }
  else { Write-Host "Result: PASS (all checks green)"; exit 0 }

Same six checks adapted for bash:
  Check 1: nc -z -w3 $POSTGRES_HOST $POSTGRES_PORT
  Check 2: nc -z -w3 $MQTT_HOST $MQTT_PORT

  Check 4: curl -sf --max-time 5 "http://$AGENT_GRPC_HOST:$AGENT_GRPC_PORT/health"
  Check 5: Parse appsettings.json with python3 -c or jq if available; check AutoAcceptUntrustedCertificates
  Check 6: ls /dev/ttyUSB* /dev/ttyACM* 2>/dev/null â€” list serial ports; WARN if none

Default variables at top of script (can be overridden by env vars):
  POSTGRES_HOST=${POSTGRES_HOST:-localhost}
  POSTGRES_PORT=${POSTGRES_PORT:-5432}
  MQTT_HOST=${MQTT_HOST:-localhost}
  MQTT_PORT=${MQTT_PORT:-1883}

  if [ $FAIL_COUNT -gt 0 ]; then echo "Result: FAIL ($FAIL_COUNT failures)"; exit 2

## TLS for MQTT (Mosquitto)

Steps to enable TLS on the Mosquitto broker:
1. Generate a CA key and self-signed CA certificate using openssl (provide exact commands).
2. Generate a server key and CSR, sign with the CA.
3. Update mosquitto/mosquitto.conf: add listener 8883 with cafile, certfile, keyfile, tls_version directives. Show exact config snippet.
4. Update Agent appsettings.json: Mqtt__UseTls=true, Mqtt__BrokerPort=8883 (or env var equivalents).
5. Update Recorder appsettings.json similarly.
6. Client connections from helix-desktop: update MqttBridge config to port 8883.

## MinIO Access Key Rotation

1. Create a new access key pair in MinIO Console (http://localhost:9002 -> Access Keys -> Create).
2. Update MINIO_ROOT_USER / MINIO_ROOT_PASSWORD in docker-compose.yml (do not reuse minioadmin in production).
3. Update Minio__AccessKey and Minio__SecretKey in Recorder appsettings.json / systemd environment or deploy/windows scripts.
4. Rotate keys: delete old key from MinIO Console after confirming the new key works.
5. Warning: the default minioadmin/minioadmin credentials must be rotated before the MinIO console port (9002) is exposed on any network interface.

## PostgreSQL Password Rotation

1. Connect to the running postgres container: docker exec -it helix-postgres psql -U helix helix_orchestration
2. Run: ALTER USER helix WITH PASSWORD 'new_strong_password';
3. Update the connection string in all places: Agent appsettings.json (ConnectionStrings__HelixOrchestration), docker-compose.yml POSTGRES_PASSWORD env var, and systemd/Windows service environment.
4. Restart affected services: docker compose restart helix-agent (or systemctl restart helix-agent).

## OPC UA Certificate Validation

1. In production, set AutoAcceptUntrustedCertificates to false in Agent appsettings.json (OpcUa section).
2. Import the device's certificate into the Agent's trusted certificate store (path configured in OpcUa__CertificateStore).
3. The pre-flight script (deploy/preflight/preflight.ps1 or preflight.sh) will WARN if AutoAcceptUntrustedCertificates is true â€” treat this as a blocker before connecting to production OPC UA devices.
