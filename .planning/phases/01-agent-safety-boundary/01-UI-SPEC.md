## Color

Retain existing desktop tokens; approximate surface distribution is 60% base, 30% secondary, 10% accent. Critical status is semantic and must not be treated as a decorative accent.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-bg` `#1e1e2e` | Main workspace and negative space |
| Secondary (30%) | `--color-surface` `#252535`; overlay `#2e2e42` | Dock panels, event cards, expanded diagnostic surface |
| Accent (10%) | `--color-primary` `#9d7fff` | Primary “Start simulation” action, selected workspace/panel state, keyboard focus ring only |
| Destructive | `--color-danger` `#ff5555` | Abort confirmation/action, rejected command, safety-triggered or faulted state |

Accent reserved for: primary action, selected navigation/panel, and keyboard focus. Never use accent for every interactive element. Preserve the existing semantic tokens: success `#50fa7b`, warning/hold `#f5a623`, muted info `#89b4fa`; always pair each status color with a text label and accessible status/alert semantics. Rejected, held, aborted, safety, and reconciliation events are prominent; routine successful events remain visually quiet.

## Phase-Specific UI and Interaction Contract

### Local authority and command admission

- Keep the authenticated local-Agent/session state visible in the execution surface. All local-Agent requests, including reads, require the authenticated session. Show the verified scientist identity; never expose session credentials in renderer-visible state, URLs, or event details.
- All renderer actions are proposals/control requests through the native desktop broker to the loopback-only local Agent. Do not show a Site Server route, a direct-device action, or a real-hardware control in this phase.
- Separate proposal feedback from dispatch status. Show a compact admission checklist for capability, safety, lease, resource, budget, and termination. Each check has a readable `Passed`, `Failed`, or `Unknown` label and expandable diagnostic detail.
- A known ordinary validation failure is shown as **Rejected — not dispatched**, with the operator-facing reason and failed-check details. Unknown/unsafe safety, lease, or device-health state is a prominent **Held for scientist review** state, not a failed/green command or an invitation to continue.
- Show compile/proposal-time checks as feedback only. The accepted runtime admission result is authoritative for the actual dispatch; the interface must not imply that an earlier green check guarantees dispatch.
- Disable dispatch while the local Agent/session is unavailable, the proposal is invalid, or admission remains unresolved. Keep pause/hold/abort distinct from dispatch and reflect their durable acknowledged state before presenting them as complete.

### Execution control and recovery

- Present `Pause`, `Hold`, and `Abort` as distinct controls and states. Pause stops future dispatch at a safe boundary; Hold blocks continuation for review; Abort is terminal. Do not imply cancellation undoes an in-flight device effect.
- Require the explicit confirmation above for Abort. Do not add destructive actions to immutable history entries.
- On restart with an intent but no trustworthy outcome, show **Held pending reconciliation** prominently. Do not offer “Retry command.” The Agent queries simulator state; a matching expected state may resume automatically and adds a conspicuous recovery event. An unreadable/nonmatching state remains held for scientist review.
- Show any operator context as a new attributable, append-only **Add review note** event. Never permit editing or deleting original intent, check, dispatch, or observation facts. A review note does not itself release a hold or bypass fresh admission.

### Command evidence timeline

- The primary evidence surface is a chronological, append-only timeline of proposals, admission decisions, dispatches, observations, recovery, holds, and aborts. Order by durable sequence/cursor; timestamps are displayed evidence, not the sole ordering key.
- The collapsed row is outcome-first and contains action, device/capability, timestamp, actor, and outcome. Expand a row to inspect parameters, validation checks, stable command/correlation identifiers, and observation/reconciliation details.
- Reload and reconnect from durable history; merge notifications by stable identity so events are neither lost nor duplicated. Provide access to completed history rather than clearing it when a run ends.
- Distinguish verified actor from any claimed identity on denied access attempts. Never display secrets. Missing/non-applicable evidence fields are explicitly labeled `Not recorded` or `Unavailable`, not silently fabricated.
- Use text and semantic icons/accessible names in addition to color. Do not animate ordinary successful events; use a persistent banner/alert treatment for safety, hold, abort, rejection, and recovery.
