# Phase 6.1 Plan 01: CapabilityDescriptor + Device Status Events + Execute Endpoint Summary

**One-liner:** CapabilityDescriptor schema types, DeviceStatusEvent/ManualActionEvent records, POST /devices/{id}/execute endpoint, and AgentService adapter health poll loop.

## Tasks Completed: 3/3

### Task 1: Create CapabilityDescriptor.cs + append DeviceStatusEvent + ManualActionEvent

Created `Helix.Orchestration.Core/Capabilities/CapabilityDescriptor.cs` with:
- `ParameterType` enum (Numeric, Boolean, Enum, String, Duration)
- `CapabilityCategory` enum (Control, Measurement, Status, Utility)
- `ParameterSchema` record (9 parameters covering type, unit, range, options, default)
- `CapabilityDescriptor` record (VerbName, DisplayName, Description, Category, Parameters, IsDestructive, RequiresActiveRunspace)

Appended to `Helix.Orchestration.Agent/Events/RunspaceEvent.cs`:
- `DeviceStatusEvent` (type="device-status", DeviceId, Status, Capabilities)
- `ManualActionEvent` (type="manual-action", DeviceId, Capability, Parameters, Success, Result, Error)

Commit: `8811f19`

### Task 2: Update DeviceEndpoints.cs — CapabilityDescriptor[] response + POST execute

Updated `Helix.Orchestration.Agent/Api/DeviceEndpoints.cs`:
- `GET /devices/{id}/capabilities` now returns `CapabilityDescriptor[]` (stub descriptors with Utility category)
- `POST /devices/{id}/execute` added: accepts `ExecuteRequest(Capability, Parameters)`, calls `registry.InvokeAsync`, publishes `ManualActionEvent` via nullable emitter, returns `{ success, result, error }`
- 404 returned when device id not found in registry

Commit: `bcf87b6`

### Task 3: Wire AgentService to publish DeviceStatusEvent on adapter health change

Updated `Helix.Orchestration.Agent/AgentService.cs`:
- Added `CapabilityRegistry registry` constructor parameter
- Added `_adapterStatus Dictionary<string,string>` change-tracking field
- Launched `DeviceHealthPollLoopAsync` in `StartAsync`
- `DeviceHealthPollLoopAsync` polls every 5s, calls `IsAvailableAsync` per adapter, publishes `DeviceStatusEvent` on status change

Commit: `71563d8`

## Deviations from Plan

### Namespace correction

**1. [Rule 3 - Blocking] IRunspaceEventEmitter namespace correction**
- **Found during:** Task 2
- **Issue:** Plan stated `IRunspaceEventEmitter` is in `Helix.Orchestration.Agent.Streaming` namespace. Actual namespace is `Helix.Orchestration.Agent.Events`. The `using Helix.Orchestration.Agent.Streaming` in the original Program.cs refers to a using alias or dead import — the concrete type and interface live in the Events namespace.
- **Fix:** Used `using Helix.Orchestration.Agent.Events;` in DeviceEndpoints.cs (already correct) and removed the Streaming using from AgentService.cs since Events was already imported.
- **Files modified:** AgentService.cs, DeviceEndpoints.cs
- **Commit:** Included in 71563d8, bcf87b6

### CapabilityDescriptor.cs file write path issue

**2. [Rule 3 - Tooling] Write tool path mangling**
- **Found during:** Task 1
- **Issue:** The Write tool failed silently when given a Windows path with the display-mangled username. File was not created at the intended location.
- **Fix:** Used bash `cat > file` heredoc to create CapabilityDescriptor.cs directly.
- **Impact:** None — file was created correctly via bash. Build verified.
