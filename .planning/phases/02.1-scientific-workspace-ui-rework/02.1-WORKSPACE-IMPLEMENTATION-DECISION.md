# Workspace Implementation Decision

## Selected decision

**Disposition: `PHASE_3_RECOMMENDATION_ONLY`**

Select a bounded validation-harness recommendation, not a final workspace
implementation or promotion. The harness consumes cited Agent/native read-model
evidence at the adapter boundary and applies the fail-closed dispositions in
[`02.1-RECONCILIATION-COMPARATOR-DISCOVERY.md`](./02.1-RECONCILIATION-COMPARATOR-DISCOVERY.md).

- **Adapter boundary:** `useAgentHealth` supplies the native-broker health
  observation and `useScientificOperation.reconcile` supplies the Agent-backed
  immutable-operation receipt. A harness adapter may read and compare these
  values; it must not create or infer authoritative safety or execution state.
- **Comparator mount:** `HelixShell` to `WorkspaceLayout`. This is the existing
  composition seam for health, runspace events, selected execution identity,
  and workspace presentation. This plan does not alter that legacy layout.
- **Selected behavior:** allow `editable` only for the exact supported healthy
  evidence described in the tracer. Held, reconciling, faulted, uncertain,
  missing, and contradictory evidence are `read-only`. Any unknown future
  state also fails closed to `read-only`.

## Phase 3 handoff and clean-room fence

Phase 3 is the **sole owner** of final primary-workspace implementation and any
final promotion decision. It must implement the D-01 workflow-board direction
instead of restoring Cards or Graph as alternate primary modes (D-01), create
an independently authored and visually/functionally distinct clean-room board
(D-02), and retain provenance for all terminology, interaction design, visuals,
layout, API contracts, assets, and branding without copying or adapting IvoryOS
expression (D-03). The Phase 2.1 direction supersedes the prior Phase 3
cards-first/graph-navigation choice, but this decision does not edit or
implement Phase 3 work (D-04).

The legacy workspace remains comparator evidence only. A final board cannot be
promoted from this recommendation: it requires the recorded comparative,
keyboard-only, screen-reader, task-based, and explicit scientist-approval gate
specified for Phase 3.

## Authority, reconciliation, and immutable evidence constraints

The validation harness is proposal/read-model evidence only (D-05). It cannot
address drivers, execute physical commands, grant approval, confirm execution,
or bypass the local Helix Agent's deterministic capability, safety, lease,
resource, budget, or termination validation. The Agent remains the sole
physical-execution authority.

For held, reconciling, faulted, uncertain, missing, and contradictory evidence,
Phase 3 must make the board read-only across pointer, keyboard, shortcuts,
inspector controls, and route changes (D-06). Its persistent status strip must
identify the cited state and available evidence, provide only recovery routes to
safety/evidence/reconciliation views, and never resemble an execution,
acknowledgement, or confirmation control (D-07).

The recommendation preserves immutable identities: it carries exact revision
identities, frozen references, independent procedure/plan revisions, samples,
custody, and lineage without substituting renderer-local state or labels (D-09).
If a future board has a pending draft, its revision, route, or procedure switch
must offer Save, Discard, or Keep editing; it must never silently retarget or
alter the scientific draft (D-08).
