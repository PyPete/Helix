# Phase 2.1: Scientific Workspace UI Rework - Context

**Gathered:** 2026-11-02
**Status:** Ready for planning

<domain>
## Phase Boundary

Establish and validate the original, accessible, safety-truthful workflow-board direction for the scientific workspace used to inspect and author revisioned apparatus, procedures, experiment plans, samples, lineage, and execution status. This urgent redesign resolves the pending workspace representation decisions from Phase 2 and supplies the binding direction that downstream Phase 3 planning must follow. It does not change Phase 2 domain/backend semantics, scientific record immutability, sample and lineage provenance, or the Agent-only execution and safety boundary.

</domain>

<decisions>
## Implementation Decisions

### Workspace direction and clean-room provenance
- **D-01 (LOCKED):** Replace the Cards and Graph workspace modes with one original workflow board as the primary scientific-workspace representation. Cards and a separate graph navigation mode are not alternate primary modes and must not be preserved as a toggle.
- **D-02 (LOCKED):** The workflow board may use IvoryOS only as behavioral inspiration for a clean-room scientific-workflow-board concept. It must be independently authored and visually/functionally distinct.
- **D-03 (LOCKED — absolute fence):** Do not copy or adapt any IvoryOS source code, UI, styles, text, layout, assets, APIs, names, logos, or branding. The work must remain MIT-only clean room. Preserve and document provenance for the independent terminology, interaction design, visuals, layout, API contracts, assets, and branding used by the board.
- **D-04 (LOCKED):** This Phase 2.1 direction supersedes Phase 3's existing cards-first with on-demand graph navigation decision. Do not edit Phase 3's context during this discuss phase; Phase 3 research and planning must treat this document as the downstream supersession requirement and revise its planned scope accordingly.

### Authority, safety truthfulness, and reconciliation
- **D-05 (LOCKED):** The workflow board constructs and displays scientific proposals only. It must never imply that board interaction can address a driver, dispatch a physical command, grant approval, or confirm execution. The local Helix Agent remains the only authority for physical execution and deterministic capability, safety, lease, resource, budget, and termination validation.
- **D-06 (LOCKED):** When Agent state is held, reconciling, faulted, or uncertain, make the board read-only. Do not leave editable affordances available through keyboard, pointer, shortcuts, inspector controls, or route changes.
- **D-07 (LOCKED):** Display a persistent reconciliation status strip in those states. It must identify the state, surface available evidence/status context, and provide recovery routes to the relevant safety, evidence, or reconciliation views; it must contain no control that looks like an execution command, acknowledgement, or confirmation.

### Draft and immutable-revision handling
- **D-08 (LOCKED):** Switching a revision, route, or procedure while edits are pending requires an explicit three-way choice: **Save**, **Discard**, or **Keep editing**. Never silently autosave, retarget, reroute, reassign, publish, or otherwise alter a scientific draft.
- **D-09 (LOCKED):** Published and approved revisions are immutable. Board presentation and navigation must preserve Phase 2's exact revision identities, frozen references, independent procedure/plan revisions, sample identities, custody, and lineage rather than replacing them with local UI state or labels.

### Validation and promotion gate
- **D-10 (LOCKED):** Promotion of the new board direction requires an accessibility and comparative-UAT approval gate before it is accepted for downstream use.
- **D-11 (LOCKED):** The gate must include task-based comparison against the legacy workspace, keyboard-only validation, screen-reader validation, explicit scientist approval, and recorded outcomes/evidence. No preference, prototype result, or automated check alone promotes the redesign.

### the agent's Discretion
- Choose the board's independently authored visual language, component architecture, information density, and non-authorizing navigation mechanics, provided every locked clean-room, authority, reconciliation, revision, and validation constraint is met.
- Select the test tooling and evidence-recording format needed to make the comparative and accessibility gate repeatable; do not weaken the required task-based, keyboard, screen-reader, and explicit-approval coverage.

</decisions>

<specifics>
## Specific Ideas

- The intended experience is an original clean-room, IvoryOS-inspired workflow-board concept: take inspiration only from behavior at a high level, not from any implementable expression of IvoryOS.
- The persistent reconciliation strip is safety evidence and recovery navigation, not a surrogate device-control surface.
- The revision-switch prompt must protect a scientist's draft from loss or semantic retargeting; **Keep editing** retains the current draft in its current context rather than accepting the requested switch.

</specifics>
