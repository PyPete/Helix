# Reconciliation Comparator Discovery

## Scope and boundary

This is a read-model evidence tracer for the bounded Phase 2.1 validation
harness. It does not implement a workflow board, change the legacy docked
layout, or promote a replacement workspace. The existing layout is retained
only as comparator evidence. Phase 7 is the sole owner of final
primary-workspace implementation and of any final promotion decision.

The current desktop has two independently observed inputs: the native-broker
health read in `useAgentHealth`, and the selected runspace lifecycle maintained
by `HelixShell`. The current sources do not expose a complete reconciled board
state. Therefore every unavailable, ambiguous, or conflicting condition fails
closed as `read-only`; Phase 7 must not infer a safe state from renderer-local
state.

## Harness contract

- **Adapter boundary:** consume only the existing native-broker/Agent read-model
  seams: `useAgentHealth` for the native health observation and
  `useScientificOperation.reconcile` for immutable operation receipt evidence.
  The harness may adapt these observations into a comparator input, but it must
  not synthesize an Agent state.
- **Comparator mount:** mount the bounded comparator at the `HelixShell` to
  `WorkspaceLayout` boundary, where `HelixShell` already composes health and
  runspace inputs. The mount is advisory/read-only and does not change
  `WorkspaceLayout` or the legacy dock layout in this plan.
- **Fail-closed rule:** only the supported exact `healthy` native observation
  may select `editable`; all other rows are `read-only`. Absent a native
  comparison result, a renderer must select `missing` or `contradictory`, never
  infer safety from a local event or cached lifecycle.
- **Identity and provenance:** carry operation, execution, apparatus, revision,
  sample, custody, lineage, and frozen-reference identifiers unchanged. The
  harness may display read-model evidence but cannot replace immutable
  identifiers with local labels or create new scientific evidence.
- **Authority fence:** the harness is proposal/read-model evidence only. It
  cannot address drivers, execute physical commands, grant approval, confirm
  execution, or bypass deterministic Agent capability, safety, lease, resource,
  budget, or termination validation.

## Comparator evidence boundary

The legacy layout is a comparison baseline only. A future Phase 7 comparative
and accessibility gate must record keyboard, screen-reader, task-based, and
scientist-approval evidence before any promotion. This discovery neither
implements the final clean-room board nor authorizes its promotion.
