## Binding implementation boundary

Build an independent MIT-only clean-room Helix Designer. Do not copy or adapt IvoryOS source, shared UI, styles, exact text/layout, assets, API shapes, names/logos, or branding. Preserve independent provenance for terminology, visuals, layout, APIs, assets, and branding.

The Designer is proposal-only. The local Helix Agent remains the only authority that can address drivers or execute physical commands after deterministic validation. This phase does not alter Phase 2 implementation.

## Required scope

- Cards-first workflow navigation with an on-demand relationship/parallelism graph.
- Agent-declared logical capability palette and typed inspector for bindings, units, defaults, provenance, quality/review state, and resources.
- Explicit If/Else True/False ports and evidence placeholder; explicit Fork/Join with Agent resource/lease diagnostics.
- Resolve-first local drafts: selection changes require Save, Discard, or Keep editing; no silent retain/reassign/autosave/retarget/approve/dispatch/application to reviewed runs.
- Persistent status-and-route reconciliation strip; held/uncertain state routes to safety/evidence and provides no direct Pause/Hold/Abort while reconciliation is pending.
- Visible Draft → Agent preflight → scientist approval → observed execution lifecycle.
- Comparative cards-first versus repaired-hybrid UX validation and graph renderer acceptance checks before graph usability evidence is accepted.
