    Step A — Add Swashbuckle CLI to SiteServer csproj.

    Edit Helix.Orchestration.SiteServer/Helix.Orchestration.SiteServer.csproj. Add inside the existing ItemGroup that has PackageReference entries:
      &lt;PackageReference Include="Swashbuckle.AspNetCore.Cli" Version="7.*" /&gt;

    The existing csproj already has Swashbuckle.AspNetCore 7.* — the CLI package ships in the same version family.

    Install the Swashbuckle CLI as a local dotnet tool (NOT DotNetCliToolReference -- that mechanism is obsolete in .NET 10 and unsupported in SDK-style projects targeting net10.0). Create or update .config/dotnet-tools.json at the monorepo root:
      {
        "version": 1,
        "isRoot": true,
        "tools": {
          "swashbuckle.aspnetcore.cli": {
            "version": "7.3.1",
            "commands": ["dotnet-swagger"]
          }
        }
      }
    If .config/dotnet-tools.json already exists, merge in the swashbuckle.aspnetcore.cli entry. Run dotnet tool restore to install the tool.

    After dotnet tool restore, invoke as:
      dotnet swagger tofile --output &lt;path&gt; &lt;assembly-path&gt; v1
    The assembly path is the published/built output of the SiteServer project.

    Step B — Write docs-site/scripts/generate-openapi.js.

    Create the directory docs-site/scripts/ and write generate-openapi.js. The script must:
    1. Determine the monorepo root by walking up from __dirname until finding Helix.Orchestration.SiteServer.csproj (or use a relative path: path.resolve(__dirname, '../../Helix.Orchestration.SiteServer')).
    2. Check whether the SiteServer has been built (look for the Release build output at Helix.Orchestration.SiteServer/bin/Release/net10.0/Helix.Orchestration.SiteServer.dll). If the binary does not exist, print a warning: "WARNING: SiteServer binary not found at expected path — skipping OpenAPI generation. Build Helix.Orchestration.SiteServer first." and exit 0 (do not fail the docs build for a missing binary — the static REST docs page will still render).
    3. If the binary exists, run: dotnet swagger tofile --output docs-site/static/openapi.json &lt;assembly-path&gt; v1 using Node.js child_process.execSync.
    4. On success, print: "OpenAPI spec written to docs-site/static/openapi.json"
    5. On error, print the stderr and exit 0 (graceful fallback — docs build must not break if SiteServer is not built).

    Use Node.js built-in modules only (path, fs, child_process) — no npm dependencies in the script itself.

    Step C — Add prebuild npm script to docs-site/package.json.

    Edit docs-site/package.json. Add a "prebuild" script entry:
      "prebuild": "node scripts/generate-openapi.js"

    Also add a "prestart" entry (for local dev):
      "prestart": "node scripts/generate-openapi.js"

    Note: The prebuild hook runs automatically before "npm run build" — this ensures openapi.json is regenerated on every CI docs build if the SiteServer binary is present.

    Step D — Add docusaurus-plugin-redoc to docs-site.

    In docs-site/, run: npm install --save docusaurus-plugin-redoc redoc
    Verify the installed version supports Docusaurus 3: check that docusaurus-plugin-redoc v2.x is installed (not v1.x which targets Docusaurus 2).
    **Fallback:** If docusaurus-plugin-redoc fails to install or causes build errors with Docusaurus 3, use a plain .mdx file instead: create docs-site/src/pages/api/rest.mdx with a <RedocStandalone> component import, or simply link to the static openapi.json file. The endpoint summary table in rest-api.md (Task 2) is always present regardless of plugin status -- F4 is satisfied by the table alone if the Redocly embed is unavailable.

    If docusaurus-plugin-redoc v2.x installs successfully, add the plugin to docusaurus.config.ts in the plugins array:
      plugins: [
        [
          'docusaurus-plugin-redoc',
          {
            id: 'rest-api',
            specUrl: '/openapi.json',
            routePath: '/api/rest',
          },
        ],
      ],

    This creates a dedicated /api/rest route. The rest-api.md doc page will link to it via a simple [View REST API Reference](/api/rest) link rather than embedding it inline (Redocly plugin generates its own page).

    Also create docs-site/static/openapi.json as a minimal placeholder so npm run build does not fail when the SiteServer binary is absent during CI. The placeholder must be a valid minimal OpenAPI 3.0 document:
      { "openapi": "3.0.0", "info": { "title": "Helix Site Server API", "version": "v1" }, "paths": {} }
    This placeholder is overwritten by the prebuild script when the real binary is available.

    ## Overview
    Helix exposes two gRPC services defined in Helix.Orchestration.Contracts/Protos/. The C# namespace is set via `option csharp_namespace`. Package names: helix.control (agent_control.proto), helix.adapter (adapter.proto). gRPC is used for Agent ↔ SiteServer communication (IAgentProxy) and for direct client connections.

    ## AgentControl service (agent_control.proto)
    Package: helix.control
    C# namespace: Helix.Orchestration.Contracts.Control

    ### RPCs

    | RPC | Request | Response | Description |
    |-----|---------|----------|-------------|
    | SubmitExperiment | ExperimentSubmission | SubmissionAck | Submit a RunspaceDefinition JSON for execution |
    | PauseRunspace | RunspaceCommand | CommandAck | Pause a running runspace by ID |
    | ResumeRunspace | RunspaceCommand | CommandAck | Resume a paused runspace |
    | AbortRunspace | RunspaceCommand | CommandAck | Abort a running or paused runspace |
    | GetRunspaceStatus | RunspaceQuery | RunspaceStatusResponse | Get the current status of a runspace |

    ### Messages

    **ExperimentSubmission**
    | Field | Type | Description |
    |-------|------|-------------|
    | runspace_definition_json | string | Serialised RunspaceDefinition JSON |

    **SubmissionAck**
    | Field | Type | Description |
    |-------|------|-------------|
    | accepted | bool | Whether the submission was accepted |
    | runspace_id | string | Assigned runspace identifier |
    | message | string | Human-readable status or error message |

    **RunspaceCommand**
    | Field | Type | Description |
    |-------|------|-------------|
    | runspace_id | string | Target runspace identifier |

    **CommandAck**
    | Field | Type | Description |
    |-------|------|-------------|
    | success | bool | Whether the command succeeded |
    | message | string | Human-readable status or error |

    **RunspaceQuery**
    | Field | Type | Description |
    |-------|------|-------------|
    | runspace_id | string | Runspace to query |

    **RunspaceStatusResponse**
    | Field | Type | Description |
    |-------|------|-------------|
    | runspace_id | string | Runspace identifier |
    | status | string | Current status (e.g. Running, Paused, Completed, Aborted) |
    | message | string | Additional detail |

    ## DeviceAdapter service (adapter.proto)
    Package: helix.adapter
    C# namespace: Helix.Orchestration.Contracts.Adapters

    ### RPCs

    | RPC | Request | Response | Streaming | Description |
    |-----|---------|----------|-----------|-------------|
    | GetCapabilities | Empty | CapabilitiesResponse | Unary | List all capability names registered on this adapter |
    | InvokeCapability | CapabilityRequest | CapabilityResponse | Unary | Invoke a named capability with JSON parameters |
    | StreamTrends | Empty | TrendValue | Server streaming | Stream live trend samples from the adapter |
    | HealthCheck | Empty | HealthStatus | Unary | Check adapter connectivity and health |

    ### Messages

    **CapabilitiesResponse**
    | Field | Type | Description |
    |-------|------|-------------|
    | capabilities | repeated string | List of registered capability names |

    **CapabilityRequest**
    | Field | Type | Description |
    |-------|------|-------------|
    | capability_name | string | Name of the capability to invoke |
    | parameters_json | string | JSON-encoded parameter object |
    | lease_id | string | Optional lease identifier for exclusive access |

    **CapabilityResponse**
    | Field | Type | Description |
    |-------|------|-------------|
    | success | bool | Whether invocation succeeded |
    | result_json | string | JSON-encoded result value (if any) |
    | error_message | string | Error detail on failure |

    **TrendValue**
    | Field | Type | Description |
    |-------|------|-------------|
    | trend_name | string | Trend identifier (e.g. "vapourtec.temperature.A") |
    | value_json | string | JSON-encoded measurement value |
    | type_tag | string | Type hint (e.g. "scalar", "spectrum") |
    | timestamp_utc_ticks | int64 | UTC timestamp in .NET Ticks |

    **HealthStatus**
    | Field | Type | Description |
    |-------|------|-------------|
    | healthy | bool | True if the adapter transport is connected |
    | message | string | Status description |

    **Empty** — no fields (used as a placeholder request/response).

      var channel = GrpcChannel.ForAddress("http://localhost:5050");
      var client = new AgentControl.AgentControlClient(channel);
    Port 5050 is the default Agent gRPC port (configurable via ASPNETCORE_URLS or Kestrel config).
