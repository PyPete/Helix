    ## Overview
    Explain that all device adapters extend DeviceAdapterBase (namespace Helix.Orchestration.Devices.Abstractions). The base class provides: capability dispatch via CapabilityDispatchBuilder, transport lifecycle management (ConnectAsync/DisposeAsync), trend streaming skeleton, and health check via transport status.

    ## Step 1: Choose and inject a transport
    Explain the three transport types: SerialDeviceTransport (RS-232/RS-485 devices), TcpDeviceTransport (Ethernet instruments), OpcDeviceTransport (OPC UA servers). The VapourtecR4 uses SerialDeviceTransport because the R4 communicates over RS-232.

    Constructor signature for VapourtecR4:
      public VapourtecR4(SerialDeviceTransport transport, ILogger<VapourtecR4> logger) : base(transport, logger)

    Note that the transport is passed to base — DeviceAdapterBase stores it as the protected Transport property (type IDeviceTransport, which SerialDeviceTransport implements via SendReceiveAsync).

    ## Step 2: Register capabilities in RegisterCapabilities
    Override the abstract method RegisterCapabilities(CapabilityDispatchBuilder builder). The builder offers two registration paths:

    - builder.RegisterSimple(name, description, handler) — for zero-parameter capabilities (e.g. Start, Stop, GetFirmwareVersion). The Start capability sends "PN \r\n" then "FW PN \r\n", checks the response prefix for "OK" or "ERR".
    - builder.Register(descriptor, handler) — for parameterised capabilities; descriptor is created with CapabilityDescriptor.CreateWithSchemas(name, description, parameterSchema) where parameterSchema is a JSON Schema string.

    Example: SetFlowRate registers with JSON Schema constraining pump (integer 0-3) and rateMlMin (number 0-9.99). The handler calls Transport.SendReceiveAsync with either "FR {pump} {rateInt} \r\n" (pumps 0-1) or "FW FR {pump-2} {rateInt} \r\n" (pumps 2-3), where rateInt = (int)(rateMlMin * 1000).

    Example: SetTemperature sends "R4 ST {reactor} {targetCelsius} \r\n".

    All commands encode with Encoding.ASCII.GetBytes and decode the response with Encoding.ASCII.GetString(response).Trim(). Responses starting with "ERR" → CapabilityInvocationResult.Failed(...). Responses starting with "OK" → CapabilityInvocationResult.Successful().

    Show the complete list of VapourtecR4 capabilities as a Markdown table:

    | Capability | Command(s) | Parameters | Notes |
    |---|---|---|---|
    | Start | PN \r\n, FW PN \r\n | none | Starts all pumps |
    | Stop | PF\r\n, FW PF\r\n | none | Stops all pumps |
    | SetFlowRate | FR / FW FR | pump (0-3), rateMlMin (0-9.99) | rate encoded as integer * 1000 |
    | SetTemperature | R4 ST | reactor, targetCelsius (0-150) | reactor index from device config |
    | SelectReagent | KP 1/3, FW KP 1/3 | channel (0-3) | reagent valve position |
    | SelectSolvent | KP 0/2, FW KP 0/2 | channel (0-3) | solvent valve position |
    | SelectLoopFill | KP 4/6, FW KP 4/6 | loop (0-3) | loop fill valve |
    | SelectLoopInject | KP 5/7, FW KP 5/7 | loop (0-3) | loop inject valve |
    | GetFirmwareVersion | GV\r\n | none | Returns version string |
    | GetTemperatures | HT\r\n | none | Returns JSON object with reactor labels A-D |

    ## Step 3: Implement trend streaming (optional)
    Override StreamTrendsAsync to yield TrendSample values. VapourtecR4 polls HT every 2 seconds for temperature trends (trend name pattern: "vapourtec.temperature.{A|B|C|D}", unit "C") and HF for flow trends ("vapourtec.flow.pumpA" / "vapourtec.flow.pumpB", unit "ml/min"). HT response format: entries separated by '&'; last entry fields are comma-separated; reactor temps are at field indices 2, 4, 6, 8 (divide by 10 for degrees C; skip -1000.0 which means "not installed"). HF response: field [1] = pump A raw (divide by 1000 for ml/min), field [2] = pump B raw.

    Then inside the CapabilityRegistry factory lambda, retrieve the adapter, iterate its capabilities, and register each with a namespaced key (e.g. "vapourtec.SetTemperature") via registry.Register(key, new HelixAdapterCapabilityBridge(adapter)).

    ## Overview
    All device communication in Helix is abstracted through the IDeviceTransport interface (Helix.Orchestration.Devices). The interface exposes: ConnectAsync, DisconnectAsync, SendReceiveAsync(byte[] request, CancellationToken) → Task<byte[]>, Status (TransportStatus enum: Disconnected, Connected, Faulted), and DisposeAsync. DeviceAdapterBase holds an IDeviceTransport reference and calls ConnectAsync during StartAsync.

    ## Serial Transport (SerialDeviceTransport)
    Location: Helix.Orchestration.Devices/Transports/Serial/SerialDeviceTransport.cs
    Configuration class: SerialTransportOptions — fields: PortName (e.g. "COM3"), BaudRate (default 9600), CommandTerminator ("\r\n" or "\r"), DataBits (default 8), Parity (System.IO.Ports.Parity enum, default None).
    Lifecycle: constructed with SerialTransportOptions and ILogger; ConnectAsync opens the port; SendReceiveAsync writes the command bytes then reads until the terminator byte or timeout; DisconnectAsync closes the port.
    DI note: the transport must be registered as Singleton to match the Singleton lifetime of CapabilityRegistry — a Transient transport captured by a Singleton registry causes a DI scope mismatch (Phase 1 A7 fix; Phase 2 B7 fix).
    Example SerialTransportOptions for VapourtecR4: PortName "COM3", BaudRate 19200, CommandTerminator "\r\n". For KnauerP2And4Pump: BaudRate 9600, CommandTerminator "\r".

    ## TCP Transport (TcpDeviceTransport)
    Location: Helix.Orchestration.Devices/Transports/Tcp/TcpDeviceTransport.cs
    Configuration: TcpTransportOptions — Host, Port, FramingMode (TcpFramingMode.Delimiter or FixedLength), DelimiterByte (e.g. 0x0D for \r, 0x0A for \n).
    Use case: Network-connected instruments (KnauerAzura at 192.168.1.101:10001 with 0x0D delimiter, Microsaic at 10.0.0.1:10001 with 0x0A delimiter).
    Lifecycle: ConnectAsync opens a TCP connection; SendReceiveAsync writes the request, reads until the delimiter byte.

    ## OPC UA Transport (OpcDeviceTransport)
    Location: Helix.Orchestration.Devices/Transports/Opc/OpcDeviceTransport.cs
    Configuration: OpcTransportOptions — EndpointUrl (e.g. "opc.tcp://localhost:4840"), AutoAcceptUntrustedCertificates (must be false in production — hardcoding true was the Phase 1 A5 finding).
    Use case: Instruments with OPC UA servers (SystagOpcUaClient at opc.tcp://localhost:4840, Mettler EasyMax/Fbrm/ReactIr at opc.tcp://localhost:4841-4843).
    Lifecycle: ConnectAsync creates an OPC Foundation session; SendReceiveAsync translates the byte request into an OPC node read/write via OpcFoundationSession.

    ## ISerialTransport (legacy test seam)
    Location: Helix.Orchestration.Devices/Transport/ISerialTransport.cs
    An older interface used in Phase 2/3 unit tests as a test double. It exposes Open(portName, baudRate = 9600), Close(), SendCommand(string), SendCommand(byte[]), SendCommandFixedResponse(byte[], expectedBytes). New adapters use IDeviceTransport/SerialDeviceTransport instead; ISerialTransport is retained for existing tests.

    ## Connection Lifecycle Diagram
    Add a simple Mermaid sequence diagram: DI container → DeviceAdapterBase.StartAsync → Transport.ConnectAsync → connected state → capability invocation → Transport.SendReceiveAsync → device response → DisposeAsync → Transport.DisposeAsync.

    ## Choosing a Transport
    Add a decision table:

    | Device interface | Transport class | Notes |
    |---|---|---|
    | RS-232 / RS-485 serial | SerialDeviceTransport | Set BaudRate, CommandTerminator to match device spec |
    | Ethernet TCP/IP | TcpDeviceTransport | Use Delimiter framing for text protocols, FixedLength for binary |
    | OPC UA | OpcDeviceTransport | AutoAcceptUntrustedCertificates must be false in production |
    | No hardware (test/sim) | NullDeviceTransport | In-process stub — always Connected, discards all sends |
