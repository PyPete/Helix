## Executive Summary

The Helix v0.1 milestone has shipped the foundational platform: 48 device drivers ported, Tauri desktop app with workflow builder and live telemetry, site dashboard, Docusaurus documentation, and Docker deployment scripts. ## Cross-Phase Integration Findings

### BLOCKERs

**1. Agent gRPC server absent — SiteServer→Agent path dead in Docker**
- Connection: Phase 6 (REST-only Agent) → Phase 7 (SiteServer GrpcAgentProxy)
- Evidence: `Helix.Orchestration.Agent/gRPC/Server/` directory is empty; `Program.cs` has no `AddGrpc()` or `MapGrpcService<>()`
- Impact: E1, E2, E3, E4 — all experiment submission, history, and status features dead in Docker

**2. POST /devices/{id}/execute always returns 404**
- Connection: Phase 6.1 (DeviceManualControl.tsx) → Phase 6 (DeviceEndpoints.cs)
- Evidence: `DeviceEndpoints.cs` line 136 `allNames.Contains(id)` where `allNames` has keys like `"simulator.SetFlow"` and `id` is `"simulator"` — always false
- Impact: C7, C9

**3. docker-compose.yml missing SiteServer ConnectionStrings**
- Connection: Phase 10 (docker-compose) → Phase 1 (AddHelixInfrastructure)
- Evidence: SiteServer environment block in `docker-compose.yml` has no `ConnectionStrings__HelixOrchestration` entry
- Impact: E1-E4, G2

**4. Agent DeviceRegistry empty — DeviceAction compilation fails**
- Connection: Phase 6.2 (DeviceActionNode) → Phase 6 (WslCompiler.ValidateDeviceBindings)
- Evidence: `Agent/Program.cs` registers empty `DeviceRegistry` singleton; no code populates it from `CapabilityRegistry`
- Impact: C4, C8

**5. DeviceRegistry.tsx fetches /health instead of /devices**
- Connection: Phase 5 (DeviceRegistry component) → Phase 6 (GET /devices endpoint)
- Evidence: `helix-desktop/src/components/DeviceRegistry.tsx` line 30: `fetch(\`${agentBaseUrl}/health\`)`
- Impact: C1

### Warnings

**W1. helix-desktop 76 tests not in CI** (D5, D6)
- ci.yml `tauri-build` job: `npm run tauri build` only; no `npm test`

**W2. SiteServer missing CORS configuration** (E5, E6)
- `AddCors`/`UseCors` absent from `SiteServer/Program.cs`; Vite dev proxy masks this in dev

**W3. SiteOverviewPage uses hardcoded placeholder data** (E1, E2)
- `PLACEHOLDER_FUMEHOODS` static array; no API call

**W4. DeviceStatusEvent emits full capability key as deviceId** (C6)
